# CLAUDE.md — working rules for the FADE repo

## What this is
FADE: tic-tac-toe where each player's oldest mark vanishes, played on a shot clock, with ratings, a bot and friend challenges shared over WhatsApp.
- Product spec: `PRD.md` (source of truth for rules, features, UI and animation)
- Phased plan: `BUILD_PLAN.md`. **Read its "v1 scope decisions" and "Road to the first APK" sections first. They override the PRD and the phases where they conflict.**

## The goal right now
Sarath wants a **first APK, built fast, that they can send a friend on WhatsApp and play online against them**. It also has a bot and pass & play, and it must feel great (PRD §7). Work through the "Road to the first APK" in BUILD_PLAN.md in order, stopping only at the checkpoints listed there.

## Stack
Expo (React Native, TypeScript strict, Expo Router) · Reanimated · React Native Skia · Gesture Handler · expo-haptics · expo-audio · Zustand · TanStack Query · Supabase (Postgres, Auth, Realtime, Edge Functions, RLS) · EAS Build (APK).

Use the latest stable versions and check current docs before using an API. Do not rely on remembered version numbers.

## Hard rules
1. Work through the road in BUILD_PLAN.md **in order**. Finish each step's acceptance checks before moving on, and stop at the agreed checkpoints.
2. **The engine (`packages/engine`) is pure TypeScript**: no React, no I/O, deterministic. All game rules live there and nowhere else, including match rules (best of 5, starter alternation, time controls, sudden death). Client, bot, solver and Edge Functions all import it.
3. **Never edit `supabase/functions/_shared/engine` or `_shared/rating` by hand.** They are generated by `npm run sync-engine`.
4. **The server is the source of truth** for online matches, clocks and ratings. Clients never write to `matches`, `moves` or `ratings`. Every table has RLS.
5. **Game animations run on the UI thread** (Reanimated worklets / Skia). No JS-thread animation during a match. Target 60 fps on a mid-range Android phone.
6. Every rule change must come with an engine test.
7. Never commit secrets. Only the Supabase publishable (anon) key goes in the app (`EXPO_PUBLIC_*`). The service-role key lives only in Edge Function secrets.
8. Never present a bot as a human player.
9. No free-text chat. Only preset emoji reactions.
10. Sounds and fonts must be properly licensed (CC0, OFL, or generated). Make our own SVG assets. If an image needs generating, ask Sarath.

## Conventions
- Monorepo with npm workspaces: `app/`, `packages/engine`, `packages/rating`, `tools/solver`, `supabase/`.
- Engine/rating imports must work unchanged in Jest, Metro and Deno (Edge Functions). Pick an import style all three accept and verify it early.
- Engine state is plain JSON (it is stored in `matches.state` as jsonb).
- Components: PascalCase files in `app/src/components`. Hooks: `useXxx`. Theme tokens only from `app/src/theme` — no hard-coded colours.
- Commit after each step with a clear message, and tick it in BUILD_PLAN.md.

## Commands (fill in as they're created)
- `npm test` — all unit tests
- `npm run typecheck` — tsc for engine (no Node types allowed) and solver
- `npm run solve -- --budget-sec=300` — re-solve 3×3, rewrite `app/assets/bot/table-3x3.json` and `tools/solver/out/results.json` (4×4 runs are time-boxed by the budget)
- Deno is not installed globally; `npx -y deno` hangs. Run the cached binary directly: `"$LOCALAPPDATA/npm-cache/_npx/42b366dd278b0c9f/node_modules/@deno/win32-x64/deno.exe" check --no-config <file>`
- `npm run sync-engine` — copy engine into `supabase/functions/_shared/engine` (generated)
- `npx -y supabase@latest functions deploy fade --use-api --no-verify-jwt --yes` — deploy the game server (after sync-engine)
- `npx -y supabase@latest db push --remote -p "$SUPABASE_DB_PASSWORD" --yes` — apply migrations
- `npm run online-smoke` — two anonymous players play a full match against the real project (needs .env loaded)
- Deno type-check needs `DENO_TLS_CA_STORE=system` on this PC (TLS interception)
- `npx expo start` — run the app in Expo Go
- `eas build -p android --profile preview --non-interactive` — build the APK
